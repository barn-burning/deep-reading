# MVP 제품 명세

## 1. 목표

deep-reading의 첫 MVP는 한 가지 질문만 검증한다.

> **질문형 비계가 사용자의 작품 이해와 자기 생각을 실제로 더 깊게 만드는가?**

회원 수, 결제 전환, 작품 DB 규모는 초기 성공 지표가 아니다.

## 2. 대상

- 중학생
- 고등학생

학년 선택은 질문의 어휘·추상도·맥락 정보의 밀도를 조정하기 위해 사용한다.

## 3. 핵심 사용자 흐름

### 시작

사용자에게 요구하는 정보:

1. 작품명
2. 작가명(선택, 동명 작품 확인용)
3. 중학생 / 고등학생
4. 작품을 읽었는지 여부

작품 전문 업로드는 MVP에서 지원하지 않는다.

### 첫 질문

처음부터 해석을 요구하지 않는다.

예:

> 방금 읽은 작품, 솔직히 어땠어?

선택 보조:

- 재밌었어
- 답답했어
- 슬펐어
- 이상했어
- 어려웠어
- 잘 모르겠어
- 직접 써볼래

사용자가 자유롭게 먼저 말하면 선택지는 생략한다.

### 탐구

한 번에 질문 하나를 보여준다.

AI는 답변을 보고 발문 엔진의 현재 상태를 판단한다.

대표 흐름:

```
반응
→ 장면/인물
→ 이유
→ 해석
→ 근거
→ 다른 가능성
→ 맥락
→ 재평가
→ 정리
```

고정된 단계 수는 없다.

권장 세션 길이:
- 짧은 탐구: 5~7턴
- 일반 탐구: 8~12턴

### 사고 흐름 패널

대화와 동시에 사용자의 사고 경로를 보여준다.

각 노드는:

- 요지
- 사고 유형
- 상태(관찰/해석/가설 등)

예:

```
사실적인 작품 속 환상적 장면이 이질적으로 느껴짐
[표현 주목]
↓
환상성이 오히려 비극성을 강화할 수 있다고 봄
[표현 효과]
↓
당시 검열 환경이 형식에 영향을 주었을 가능성을 제기
[맥락 전환 · 가설]
```

사용자는 AI가 정리한 요지를 수정할 수 있다.

### 종료

결과 페이지는 점수 대신 다음을 보여준다.

#### 내가 발견한 것
현재 비교적 확실하게 정리된 생각

#### 내가 세운 가설
추가 근거·조사가 필요한 해석

#### 생각이 달라진 지점
처음과 현재의 판단 차이

#### 아직 남은 질문
탐구를 닫지 않고 이어갈 수 있는 질문

#### 오늘 사용한 사고
예:
- 장면 주목
- 근거 찾기
- 다른 관점
- 맥락 전환

## 4. 화면 구조

데스크톱 MVP:

```
┌──────────────────────────────┬──────────────────────┐
│                              │                      │
│       탐구 대화              │      사고 흐름       │
│                              │                      │
│  AI 질문                     │  ① 첫 반응          │
│  사용자 답변                 │       ↓              │
│  AI 질문                     │  ② 해석             │
│                              │       ↓              │
│                              │  ③ 새로운 가설      │
├──────────────────────────────┴──────────────────────┤
│                답변 입력                           │
└─────────────────────────────────────────────────────┘
```

모바일에서는 사고 흐름 패널을 접을 수 있게 한다.

## 5. AI 사용 원칙

AI 호출을 매 턴 무제한으로 사용하는 구조를 목표로 하지 않는다.

초기 프로토타입에서는 품질 검증을 위해 턴 기반 호출을 허용하되, 이후 다음 최적화를 고려한다.

- 작품별 기본 발문 캐시
- 공통 발문 템플릿
- 단순 S0~S3 구간은 규칙 기반 처리
- 깊이 탐구가 필요한 턴만 AI 호출
- 세션 요약은 종료 시 한 번 생성
- 동일 작품의 배경 맥락 정보 캐시

## 6. 저작권 원칙

MVP는 작품 전문을 제공하지 않는다.

사용자가 이미 읽은 작품을 대상으로 탐구한다.

서비스 내부에서 필요한 정보:
- 작품명
- 작가
- 사용자가 기억하는 장면·표현·내용
- 서비스가 자체 제작한 발문과 탐구 구조

현대 저작물의 원문 저장·배포 기능은 별도 권리 검토 전까지 구현하지 않는다.

## 7. 초기 성공 기준

테스트 사용자에게 세션 종료 후 다음을 묻는다.

- 처음보다 작품에 대해 생각할 것이 많아졌는가?
- 질문이 특정 답으로 유도한다고 느꼈는가?
- 질문 난이도는 적절했는가?
- 혼자 읽었을 때보다 다른 관점을 발견했는가?
- 사고 흐름 정리가 실제 자기 생각과 맞았는가?
- 다른 작품으로 다시 사용하고 싶은가?

가장 중요한 정성 지표:

> “내가 원래 하던 생각보다 한 단계 더 생각하게 됐다.”

## 8. MVP에서 하지 않는 것

- 로그인
- 구독/결제
- 학급/교사 관리
- 시험 점수
- 작품 전문 라이브러리
- 랭킹
- 배지
- 자동 독후감 생성
- 학생 대신 답안 작성
